## Project Overview

Solar AI-Optimizer — a solar energy monitoring web app for Moroccan solar panel owners and installers. Connects to Huawei FusionSolar API for real-time/historical data, runs an AI model to detect panel soiling (dust reducing efficiency), and alerts users when cleaning is needed. UI is in French, currency is Moroccan dirhams (DH).

## Architecture

### Backend: FastAPI + SQLAlchemy + MySQL

```
main.py                  → App entry, creates tables, seeds demo accounts
app/
├── auth.py              → JWT auth (python-jose), bcrypt hashing, role-based access
├── config.py            → All env vars loaded here (FusionSolar, DB, JWT)
├── database.py          → SQLAlchemy engine + SessionLocal (MySQL via pymysql)
├── models.py            → ORM: User, ClientStation, Intervention (with role/status enums)
├── schemas.py           → Pydantic request/response models
├── routers/
│   ├── auth.py          → /auth/register, /login, /me
│   ├── client.py        → /client/* (requires role=client) — KPI, alerts, interventions
│   ├── employee.py      → /employee/* (requires role=employee) — client/station management
│   ├── soiling.py       → /soiling/predict, /soiling/station/{code}
│   ├── interventions.py → CRUD for maintenance tasks (shared by client + employee)
│   └── fusionsolar.py   → /api/* public proxy for FusionSolar testing
└── services/
    ├── fusionsolar.py   → FusionSolarClient singleton: login, KPI, devices, alarms (5min cache)
    ├── soiling.py       → Loads soiling_model.pkl via joblib, runs predict() with 5 features
    └── demo.py          → Fake time-aware data generators, account seeding
```

## Key Data Flow

```
FusionSolar API ──→ app/services/fusionsolar.py (cached 5min)
                         ↓
                    app/routers/client.py (checks if demo station → returns fake data)
                         ↓
                    React (api.js polls every 10min, live power every 3s)
                         ↓
                    Dashboard components
```

For demo accounts (`DEMO-STATION-001`), all KPI data is generated by `app/services/demo.py` — no real API calls are made. The demo data is time-of-day aware (solar bell curve peaking at 13:00, zero outside 6h-20h).

## AI Model

- **Location:** `ml_models/soiling_model.pkl` (currently empty — stub heuristic used)
- **Loaded by:** `app/services/soiling.py` via joblib
- **5 input features:** `radiation_intensity`, `inverter_power`, `installed_capacity`, `temperature`, `power_ratio`
- **Output:** `soiling_index` (0.0–1.0) → mapped to status: clean (<2%), light (<5%), moderate (<10%), heavy (≥10%)
- **Update process:** Teammate trains externally → exports .pkl → replace file → restart backend

## Auth & Roles

- JWT via `python-jose`, 24h expiry, payload: `{sub: user_id, role, exp}`
- Two roles: `client` (self-registers, sees own stations only) and `employee` (pre-created, manages all)
- Backend enforces role via `require_role()` dependency on each router
- Frontend stores token in `sessionStorage`, auto-redirects on 401

## Important Conventions

- **All UI text is in French** — labels, alerts, recommendations, error messages
- **Inline CSS only** — no CSS framework, styles defined as JS objects in components
- **Demo detection:** Backend checks `station_code == "DEMO-STATION-001"` to decide between real FusionSolar data and generated demo data
- **Number formatting:** French locale (`fr-FR`) — comma as decimal separator
- **Currency:** Moroccan dirhams (DH), conversion: `energy_kWh × 1.5 = DH`
- **CO₂ calculation:** `total_energy × 0.233 = kg CO₂`, trees equivalent: `co2_kg / 21`

## Database

MySQL via SQLAlchemy. Three tables:
- **users** — id, email, password_hash, full_name, role (client|employee), created_at
- **client_stations** — links clients to FusionSolar station codes
- **interventions** — maintenance tasks with type/priority/status enums and full lifecycle tracking
